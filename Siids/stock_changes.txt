Meeting Summary & Key Themes
Following a stakeholder review session with end-users of the SIIDS stock operations module, the following 25 changes were identified and 
prioritised
. Changes span all active user roles and introduce one new role (Deputy PRSO). The session surfaced four cro
ss-cutting themes that apply across all changes:
OTP Validation
Replace physical signatures with system-generated OTPs for goods seizure confirmation, owner goods return, and auction winner handover.
Reports & Charts
All four roles require a dedicated reports page with chart 
visualisation
, downloadable reports, money/finance tracking, and progressive summaries by week or month.
Advanced Sorting & Filtering
Every inventory table must support multi-dimensional sorting: by date, goods type, location, owner, reference number, and month.
Dashboard UI Depth
Information density must increase — more detail per record, status-aware actions, and clear navigation between operational states.

Cross-Cutting Requirements
The following requirements apply to all roles and all changes in this document. They must be implemented consistently across every affected screen and endpoint.
OTP Infrastructure
A single shared OTP system handles all three OTP contexts (SEIZURE_OWNER, O
WNER_RETURN, AUCTION_HANDOVER). The 
otp_verifications
 table stores all OTPs hashed. OTPs expire in 10 minutes. Verified OTPs are marked with 
verified_at
 and cannot be reused. The SMS gateway integration is shared across all contexts.
Reports Architecture
All four roles have a Reports page. Each page shares the same charting components (
Recharts
) and download infrastructure. PDF generation is server-side only — never client-side. All report PDFs include RRA letterhead, date range, user identity, and a gener
ation timestamp.
Audit Log Coverage
Every state-changing action across all roles must write to the 
audit_log
 table. This covers: seizure note creation, OTP sends and verifications, escalations, returns, approvals, rejections, delegations, and release handovers. The 
audit_log
 is append-only —
 no updates or deletes are permitted.
Finance Tracking
All monetary amounts (fines, penalties, auction proceeds) are stored in RWF (Rwandan Franc) as 
DECIMAL(
15,2). Every Release Note and Return-to-Owner Note must include a financial summary. The Reports 
pages for all roles aggregate these amounts with date filters.
Document Snapshots
All generated documents (Seizure Note, PV Document, Release Note, Return Note) must snapshot the goods description, officer identity, and owner details at the time of generation. Documents must not use live FK references that could change. Snapshots ensure
 documents remain legally accurate even if underlying records are updated.
Role Guards
Every new endpoint must enforce role-based access control at the Spring Security layer. DEPUTY_PRSO endpoints must not be accessible to STOCK_MANAGER or SURVEILLANCE_OFFICER. Delegation logic is enforced server-side — a Deputy PRSO cannot self-grant releas
e approval authority.
